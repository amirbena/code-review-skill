# Feature pages

One short page per Skill. Each says when to ask for it, what to say, and its
boundaries. You never need a Skill name: ask for the outcome in plain words
and the reviewer picks what fits ([modes](../v3-architecture/adr-v3-review-core.md)).

| Page | Skill |
|---|---|
| [`review-core`](review-core.md) | the review itself |
| [`review-publish-github`](review-publish-github.md) | post the review to the PR |
| [`review-requirements`](review-requirements.md) | check against Jira, an Issue or acceptance criteria |
| [`review-deep-investigation`](review-deep-investigation.md) | wider tracing and root cause |
| [`review-suggestions`](review-suggestions.md) | non-blocking improvement ideas |
| [`review-security`](review-security.md) | security and supply chain |
| [`review-backend`](review-backend.md) | APIs, data, concurrency, performance, deployment |
| [`review-frontend`](review-frontend.md) | UI, state, accessibility, rendering |
| [`review-runtime-check`](review-runtime-check.md) | confirm a finding by running a check |

Coming from v2? See the [migration guide](../migration-v2-to-v3.md).
