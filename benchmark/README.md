# Benchmark Corpus and Reference Examples

Corpus data and non-CI-gated reference examples for the code-review
quality benchmark (parent [#40](https://github.com/amirbena/code-review-skill/issues/40)).
Like the rest of `docs/`, this is a repository-development directory: **not**
packaged into either Skill archive, and no packaged Skill resource depends
on it.

The benchmark harness/runtime scripts and contract/schema documents were
relocated to
[`runtime_platform/benchmark/`](../../runtime_platform/benchmark/README.md)
by [#457](https://github.com/amirbena/code-review-skill/issues/457) (the
first physical migration slice of
[#425](https://github.com/amirbena/code-review-skill/issues/425)). Start
there for the fixture format, taxonomy, selection, runner, and metric
contracts, and for the harness/reference-model code. This directory keeps
only what #457 explicitly did not move:

| Path | Contents |
| --- | --- |
| [`corpus/`](corpus/README.md) | The ~180 `benchmark-case/v2` fixture corpus, organized by sub-corpus. Deferred until each `capabilities/<name>/` exists as more than a manifest (see the [benchmark ownership boundary checkpoint](../capability-architecture/benchmark-ownership-boundary-checkpoint.md)). |
| `corpus-index.json` | The deterministic, non-LLM inverted index over `corpus/`, generated by [`runtime_platform/benchmark/scripts/build_benchmark_index.py`](../../runtime_platform/benchmark/scripts/build_benchmark_index.py) — never hand-edited. |
| [`examples/`](examples/example-case.yaml) | Worked-example fixture data referenced by [`runtime_platform/benchmark/fixture-format.md`](../../runtime_platform/benchmark/fixture-format.md) and the shadow-validation burn-in report below. |
| [`cloud-routine-integration.md`](cloud-routine-integration.md) | Class 2 Cloud Routine integration doc for the scheduled sentinel/comprehensive execution lanes (#415). |
| [`reviewer-brief-examples.md`](reviewer-brief-examples.md) | Paired reference examples for the `Reviewer Brief` contract (#309). |
| [`senior-voice-examples.md`](senior-voice-examples.md) | Paired before/after reference examples for senior-voice rendering (#231). |
| [`shadow-validation-burn-in-report.md`](shadow-validation-burn-in-report.md) | Worked example of a shadow-validation burn-in report, companion to [`runtime_platform/benchmark/shadow-validation.md`](../../runtime_platform/benchmark/shadow-validation.md). |

None of these five documents is a machine contract that harness code
actively enforces the way the relocated contract docs are (see the
relocation issue for the classification rationale); they stay here as
reference/example material and scheduling documentation, adjacent to the
corpus they describe.
